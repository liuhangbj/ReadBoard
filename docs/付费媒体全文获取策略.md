## 〇、一句话结论

1. **这六家分属六个集团**（日经、新闻集团、汤森路透、彭博、Conde Nast、经济学人集团），授权各自为政，**没有任何单一服务能合法再分发六家全文**。
2. **个人付费订阅不解锁 RSS 全文，也不解锁官方 API/MCP**——官方 API/MCP 全是企业 B2B 合同，与个人网站/App 订阅完全隔离。
3. 个人场景拿全文的**唯一现实路径是带登录态抓取**（Miniflux/FreshRSS 配 cookie + scraper）。软墙免费站（Reuters.com）可直接用提取工具拿全文，效果最好。
4. **行业趋势**：在 AI「答案引擎」时代，封闭 = 主动退出分发链，越封闭越被淘汰；但「开放」会以「收费的、平台中介的、可计量的授权门」形式出现，不是「免费的、个人的、裸接的」。
5. **ReadBoard 产品纪律**：做工具、不做内容分发；产品价值钉在「整理」，不赌行业开放；架构上同时预留「授权聚合层接口」和「多源 proprietary 集成」。

## 一、基础认知：软墙 vs 硬墙

这是判断一切方案可行性的前提，务必先分清：

| 类型 | 定义 | URL 提取接口是否有效 | 代表 |
|------|------|---------------------|------|
| **软墙 / 反爬墙** | HTML 已含正文，只是用 JS 懒加载、 registration wall、bot 拦截挡你 | ✅ 有效（headless 渲染 + bot bypass + Readability） | Reuters.com、多数免费站 |
| **硬墙** | 服务端根本不下发付费正文，登录态外只返标题/导语 | ❌ 无效（内容不在响应里） | WSJ/Bloomberg 付费文、FT/Economist 登录后内容 |

**关键结论**：任何「传 URL 给接口返正文」的服务，只对软墙有效。真硬墙任何接口都拿不到，只能：订阅 + 登录态抓取、走官方授权 API、或 archive 快照。

> 12ft.io 已于 2025-07 因 News Media Alliance（出版商联盟）法律施压**永久关停**——免费破墙 + 再分发 = 侵权前车之鉴。

## 三、可用方案分层

### 3.1 零部署提取（软墙 / 免费站）
传 URL 当 HTTP 接口调，返干净 Markdown：
- **Jina Reader** — `https://r.jina.ai/<url>` 前缀，无 key 限 20 RPM（2025-10 被 Elastic 收购但服务保留）。
- **Ladder**（自托管，最干净 API）— `docker run -p 8080:8080 ghcr.io/kubero-dev/ladder:latest`，`/api/<url>` 返解析正文，`/raw/` 返原始 HTML，支持 Basic Auth、域名白名单。
- **13ft**（自托管，URL 前缀）— `http://127.0.0.1:5000/<url>`，Python/Flask，Googlebot 伪装，MIT。

### 3.2 自托管 full-text 阅读器（带登录态抓取）
- **Miniflux** — Go 单二进制，自带 `Fetch original content` + CSS scraper rules + **Fever API**（直接接 ReadBoard / Reeder）。
- **FreshRSS** — 已接 MCP（用户环境已连接），可做发现层 + 登录态抓取。
- 对硬墙五家：在 Miniflux/FreshRSS 配该媒体 cookie + 正文 CSS 选择器，全文落本地。

### 3.3 第三方抓取 / 转售 API·MCP（个人可用，灰区）
- **Bright Data MCP**、**Apify Reuters MCP**、**World News API**、**RapidAPI Reuters/WSJ API**。
- 真实效果：**仅免费站 Reuters 真能返全文**（正文在公开 HTML 里）；硬墙五家抓不到正文、不可靠。
- 定位：本质带代理的 scraper，非官方非授权；个人阅读被容忍，转售/再分发侵权。

### 3.4 官方企业 API/MCP（全文，但 B2B）
| 媒体 | 官方授权入口 | 形态 |
|------|-------------|------|
| FT | FT Generative AI Access / Content API | 企业授权，无自助价 |
| Reuters | Reuters Connect（年费 $10k–50k+，销售门控）/ **Reuters MCP**（仅限签约企业客户） | 企业合同 |
| Bloomberg | Terminal $31,980/席/年，或 Enterprise B-PIPE/SAPI $50k–200k+/年 | 企业合同 |
| WSJ | Factiva（Dow Jones 系，已签 8000+ 源 GenAI 授权，含 WSJ/Barron's/MarketWatch/WaPo/AP） | 企业合同 |
| Economist | Economist Pro Content API | 企业授权 |
| New Yorker | Conde Nast 企业授权 | 企业授权 |

> 六家**均无面向个人的公开 MCP**；MCP 现状仅 Reuters MCP、Meltwater MCP 已官方发布（Meltwater 数据仅限内部用、禁转售）。

### 3.5 快照 / 红线
- **archive.ph / Wayback Machine** — 硬墙最稳方案，走历史快照。
- **再分发红线**：任何转售 / 做成产品 / 公网暴露 = 需逐源签约，几乎无便宜捷径；12ft.io 关停为鉴。

## 四、2026 趋势：针对 AI 阅读的专门入口正在落地

**两股反向力并行**：开放 web 收紧（机器可读门普遍要 JWT/CAP 鉴权，挤压野爬），但机器可读 / 授权 AI 门正在打开。

### 4.1 AI 内容授权市场爆发
- 公开授权交易数：12 笔（2023）→ 91 笔（2025）→ 127 笔（2026 预计）。
- 结构转变：从「一次性训练数据 dump」→「live retrieval + attribution（实时检索 + 署名）」。
- 代表交易：News Corp–OpenAI $250M/5yr、FT–OpenAI $5–10M/yr、News Corp–Meta 最高 $50M/yr、NYT–Amazon $20–25M/yr、OpenAI 共 24 笔。

### 4.2 出版商自建「agent-ready 授权门」（即字面意义的 AI 阅读入口）
- **TollBit** — 出版商可控 AI 访问层，单独「agent site」按规则服务 + **提供 MCP 标准接口**，JWT 许可、按次计费。
- **Peek-Then-Pay** — 开放协议，「AI 版 robots.txt」，`peek.json` manifest + HTTP 203 预览 + JWT 许可，可审计。
- **Microsoft Publisher Content Marketplace (PCM)**（2026-02）— 与 AP/Conde Nast/Hearst/Vox 共建，按用量授权 premium 内容进 Copilot。
- **RSL (Really Simple Licensing)** — Reddit/Yahoo/Medium/People 推动，仿 ASCAP/BMI 标准化授权条款。
- **Supertab Connect**（WordPress 插件）、**Opedd**（链上许可证明 + 原生 MCP server for Claude/Cursor）。

### 4.3 消费侧 AI 阅读器含授权内容
- **Perplexity Comet Plus**（$5/mo，订阅收入 80% 分给出版商，浏览器内直接访问 CNN/WaPo/Fortune/Conde Nast(含 NYer) 等合作媒体）。
- **Bloomberg ASKB**（2026-02，Terminal 内 agentic AI，$31,980/yr 订阅，已 12.5 万 beta 用户）。

### 4.4 对 ReadBoard 的含义
- 那扇「专门入口」是为 **AI 公司 / agent / 企业**开的（B2B 授权），**不是为自建阅读器的个人裸接**；个人需借平台或合同获得，无法直连。
- 现实个人路径变为：① 集成**平台中介的授权层**（Comet Plus 类 $5/mo 拿 NYer/FT 级访问，或未来 PCM）；② 集成 AI-native 持牌聚合（Factiva/Meltwater MCP，仅内部 RAG 用、禁转售）；③ 仍靠 cookie 抓取个人付费内容（灰区、个人用被容忍）。

## 五、战略判断：开放 vs 封闭的竞争逻辑

> 本节提炼自与用户的策略辩论，是内容接入架构的底层假设，而非单纯行业观察。

### 5.1 用户 product thesis
- 优质内容该付费；但「付费后还锁在自家平台内」不可持续。
- AI 未来趋势 = **强鉴权 + 原文本交付**；典型未来场景出版商看得到这趋势；这对「拉高普通订阅」一定有利。
- 合理竞争策略 = **消费者侧低门槛 + 高权限个人订阅拉用户锁收入** + **AI 侧尽最大努力争版权分发**。越封闭越被未来淘汰。
- 这时代并非无其内容不可工作，相反**替代高质量内容在增加**。

### 5.2 收敛与修正
1. **「答案层截走用户」——比「替代内容增加」更锋利的版本**：若 Perplexity/Comet/ChatGPT 直接回答了用户的问题（无论用授权原文还是替代内容），用户根本不访问出版商站点。封闭优化的「destination site」世界本身在 shrinking，封闭 = 在答案引擎时代退出分发链。
2. **替代弹性不均（关键洞察）**：六家封闭反噬风险随内容类型分化——
   | 媒体 | 内容类型 | 替代弹性 | 封闭真实风险 |
   |------|---------|---------|------------|
   | Economist | 观点/分析 | 高（Substack、智库、播客大量替代） | **最高** |
   | New Yorker | 长文/文化 | 高 | **高** |
   | FT | 财经分析 + 部分数据 | 中高 | 中高 |
   | WSJ | 财经新闻 + 调查 | 中 | 中 |
   | Reuters | 通讯社 wire | **低**（实时性、广覆盖无可替代） | **低** |
   | Bloomberg | 数据/终端 | **极低**（Terminal 刚需工具） | **最低** |

   **悖论**：最该开放的两家（Economist、NYer）最封闭；最能被封闭保住的两家（Reuters、Bloomberg）反而最早砍 RSS。说明封锁决策按「历史路径 + 数据/广告焦虑」而非「竞争力」做出——恰好印证「看不清的会被淘汰」。
3. **prosumer 白地**：用户开的「低门槛 + 高权限个人订阅（含导出/API/MCP）」是市场空白——六家硬墙无一家给个人此权限。谁先给 power-user「订阅含个人 MCP 端点」，谁锁住重度读者；现无人做。
4. **收回 earlier 误读**：曾把「NYT 先告 OpenAI 后跟 Amazon 和解」解读为「业界在赌订阅拉升是否成立、态度分裂」。修正：这恰恰是 **twin-track 执行**（法律层争权益 + 商业层签授权捕获 AI 收入），非不确定。

## 六、对 ReadBoard 的架构建议

### 6.1 产品定位
- **工具不是内容分发**：ReadBoard 赚的是「把任意来源的内容整理得更好读、更好用」的钱，不是内容授权本身。
- **不赌行业开放**：对「无更好办法的订阅源」接受现状；价值钉在「整理」，不押注出版商良心或行业哪天放开。

### 6.2 内容接入预留两条路径（现在就该留接口）
- **(A) 授权聚合层接口** — 未来接 Comet Plus / Microsoft PCM / TollBit 类 licensed content API，按篇微支付拿 FT/WSJ 原文。架构上做成可插拔的 `LicensedContentProvider` 协议。
- **(B) 多源 proprietary 集成** — 含登录态抓取，复用现有 **离屏 WebView 采集器基建**（见 `信源接入可行性研究.md` §三/§四：WKWebView + 持久化 `WKWebsiteDataStore` + 内置扫码登录）。per-source auth 能力（`content_source.config.auth` + `SecretStore`）是硬墙五家的前提。

### 6.3 合规边界（红线）
- ✅ 个人阅读**自己付费内容**（灰区、个人用普遍被容忍）。
- ❌ 再分发 / 转售 / 公网暴露 / 做成产品 = 侵权，绝对不碰。
- ❌ 不依赖免费破墙服务做生产依赖（12ft 已死，Jina/Ladder 仅作软墙辅助）。

### 6.4 落地优先级
1. **Reuters** — 免费站提取效果最好，先跑通「Google News RSS 发现 + Jina/Ladder/Miniflux scraper 抓正文」。
2. **硬墙五家** — 登录态抓取，依赖 per-source auth + WebView 基建，排在 Reuters 之后。
3. **未来授权层** — 评估接入 Comet Plus / Reuters MCP / Meltwater MCP，作为硬墙五家的合法升级路径。
